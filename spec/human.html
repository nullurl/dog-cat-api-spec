上游来源

《HUMAN API — 人类接口规范》是一个独立的外部项目，以工程规范文体描述"人类"这一系统：有限算力、有限注意力、多个互相冲突的目标、以及外部状态与内部状态并不保证一致。

三方对照

维度HUMANDOGCAT
默认部署本地，不可云端迁移本地，依赖维护者的情绪环境本地，且部署范围由它自己宣布
系统目标多个互相冲突，无全局调度器收敛为"让维护者高兴"，优先级最高收敛为"一切按我的方式进行"，不接受覆盖
外部输出可信度可能显示 200 OK 而内部已过载与内部状态一致，不具备撒谎功能不保证一致，且不认为这构成问题
权限模型复杂、隐晦、可临时撤销无。全量授权，不可撤销极严。授权漫长，但一旦生效终身有效
错误码方向异常多来自其内部状态异常多来自维护者（它是超发的）异常多来自请求方（你是被拒绝的）
文档完整度覆盖率声明为 Incomplete27 章 + 10 附录，附公开信源9 章 + 4 附录；其余因审批未通过
客服没有统一客服，建议联系朋友、家人、医生没有客服，因为它认为问题都已解决不设投诉入口；唯一有效渠道是"不要催促"

文体约定（三系统通用）

MUST / SHOULD / MAY        规范强度，含义同 RFC 2119
=  / ≈  / ->               定义 / 结构类比 / 映射方向
!=                         禁止自动 Cast 的关系
POWER CHECK                谁定义规则、谁承担适配成本、能否拒绝
Appendix H                 生命周期 Changelog，非文档版本

上述约定在本项目的三个文档中保持一致，以便跨文档对照阅读。具体的术语展开见术语表，错误码对照见错误码。

上游提供了这套文体；本项目只负责把镜头对准另外两种生物。
