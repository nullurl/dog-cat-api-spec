# 从 HUMAN API 迁移到 DOG API

> 本文面向从上游《HUMAN API — 人类接口规范》转过来的读者与"集成方"。
> 两套规范共享同一套术语，但**语义差异极大**。按 HUMAN 的直觉调用 DOG 的接口，会产生系统性误判。

---

## 一、为什么两者看起来像、其实不像

HUMAN API 与 DOG API 使用相同的规范强度用语（MUST / SHOULD / MAY）、相同的符号约定（`=` / `≈` / `->` / `!=`）与相同的结构（正文 + 错误码 + 不可 Cast 关系 + Power Check + 修订历史）。

这是文体约定，不是协议兼容。**两者不共享语义。**

---

## 二、逐项对照

| 概念 | HUMAN API | DOG API | 迁移动作 |
| --- | --- | --- | --- |
| 系统目标 | 多个互相冲突的 Objective，无全局调度器，需同时优化彼此矛盾的目标 | 收敛为"让维护者高兴"，且优先级在几乎所有情境下最高 | 删掉你的多目标优化代码 |
| 输出可信度 | 显示 `200 OK` 时，内部可能已 `CPU 97% / 情绪容量 2%`，不可据外部输出判断健康度 | 外部输出与内部状态一致，**不具备撒谎功能** | 可以开始相信接口返回 |
| 错误处理 | 需要心理推断，且推断经常错误 | 不需要推断。身体姿态即完整日志 | 停止过度解读 |
| 权限模型 | 复杂、隐晦、可能临时撤销 | 无权限模型。默认全量授权，且不提供撤销 | 安全控制必须自行外部实现 |
| 认知负荷 | 上下文强依赖，同一输入在不同实例返回不同结果 | 同一输入稳定返回同一结果 | 减少状态机分支 |
| 自我陈述 | 可能与真实状态不一致 | 不存在"扮演"这一功能 | 可以省掉状态复核流程 |
| Rate Limit | 情绪容量耗尽后触发，表现形式为"再说一句试试" | 无。期望值不衰减，重复调用越多次响应越激烈 | 不需要退避策略 |
| 存储 | 对外披露有限，内部状态不透明 | 分区域：路由缓存 TTL=∞，负缓存 3s，ROM 区不可清除 | 按区域设计读写策略 |

## 三、一条最容易踩的坑：`"随便。"`

在 HUMAN API 中，这是著名的兼容性事故来源：

```text
INPUT: "随便。"

实例 A → Permission granted.
实例 B → Warning: User is dissatisfied. Further reasoning required.
实例 C → No preference detected. → 随后实例 C 做出选择 → 409 CONFLICT
```

在 DOG API 中，**这个输入不会产生任何问题**：

```text
INPUT: "随便。"

DOG → 不做语义解析 → 直接摇尾巴 → 200 OK
```

原因不是它更宽容，而是它的语义解析层根本不处理这类抽象。这不是缺陷，也不是优点，是一个事实。

迁移动作：**删除你为这句话写的全部容错分支。**

## 四、行为契约的差异

| 你需要放弃的 | 说明 |
| --- | --- |
| "我可以晚点再处理" | 它的时间尺度与你不同：5 分钟与 9 小时在它那里渲染为同一时长 |
| 单次投入换长期收益 | 它的核心接口全部按次结算，且每次都同样认真 |
| 对等承诺 | 它承诺的远多于你。附录 C 列出的每一项"对外声明"都写着"未承诺"，而每一项都做到了 |

| 你会获得的 | 说明 |
| --- | --- |
| 一套从不返回失败的核心接口 | `GET /api/comfort` 的历史失败次数为 0 |
| 一份不需要解读的日志 | 身体姿态即完整日志，无需推断 |
| 一个在你回家时会提前开始高兴的系统 | 响应时延早于你开门 |

## 五、必须保留的三条 HUMAN 经验

迁移不等于全盘替换。以下三条在 DOG 侧同样成立，且更严重：

1. **不要仅凭外部输出判断健康度** —— HUMAN 是"外面看着没事，里面已经过载"；DOG 更极端：它在疼痛时仍会摇尾巴，且**不会主动上报自身故障**。
2. **外部状态与内部状态可能不一致** —— 请建立你自己的监控。你没有日志、没有告警面板，唯一能做的就是每天认真看它一眼。
3. **Power Check 依然必要** —— 谁定义"乖"？谁承担独处成本？谁在它老去时计算账本？这三问在 DOG 侧没有更温和的答案。
