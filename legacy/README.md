# 历史存档（legacy）

这里放**已冻结**的历史形态，不放当前内容。

## 为什么会有这个目录

`assets/js/data-dog.js` 的第一行注释写着「由 legacy 单文件版本提取生成」。本目录里的
`api-spec-variants.html` 就是那个单文件版本 —— 在 0.8.0「项目化」之前，这份规范是
一个 HTML 文件，数据、样式、渲染逻辑全在里面，双击即开，不依赖任何外部资源。

把提取来源一并发布，是为了让那句注释**可核验**：读者可以打开存档文件，对照它和当前
站点是不是同一份东西。

## 内容

| 文件 | 是什么 | 大小 |
| --- | --- | --- |
| `api-spec-variants.html` | 单文件形态的最后一版，正文 27 章 | 约 66 KB |

自包含：没有 `src`、没有外部 `href`、没有 `fetch()`。离线可读。

## 版本轴

这个项目里同时存在几个互不相干的「版本号」。完整的表在 [../versions.html](../versions.html)，
这里只记一条与本目录直接相关的：

**节号会整体平移。** 附录字母按数组位置派生：中间删掉一条，其后所有字母前移，全站十几处「附录 X」
引用同时失效。本项目真实发生过一次，处理方式是就地改写内容、保持字母不动。

同一件事在正文上更明显，而且本项目里有**两套**正文编号。`api-spec-variants.html` 里的 27 章用的是
两位全局列号 `00`–`26`；DOG 正文后来长到 35 章（插入都发生在中间），并在 0.18 整体改为 `§X.Y` 并入
5 个 PART；CAT 正文则仍是两位列号 `00`–`08`。所以存档里的 `§07`
**在当前的站点上根本不存在** —— 它既不是现在 DOG 的 `§2.2`，也不是别的什么，
它只是当时那个文件的第 8 章。要定位它，只能用规范 ID。

**结论：跨版本引用用规范 ID，不要用节号。** 登记表见 [`../reference/norm-ids.html`](../reference/norm-ids.html)。

## 与子集仓库那份副本的关系

DOG API 子集仓库（`dog-api-spec`）的 `archive/` 里有一份**副本**，供那个仓库自包含地核验同一条注释。
那份副本为与该仓库的范围（仅 DOG）一致，做了三处改动 —— CAT 文档本体与路由分支被移除、
章标题去掉上游项目名、侧栏版本行标注为档案版本；三处都记在副本自己的 `archive/README.md` 里。

**本目录这一份是原版，逐字未改**，含 CAT 文档本体与全部上游引用。

## 规则

**本目录只增不改。** 存档文件一旦写入就不再编辑：它存在的意义是「当时是什么样」，
而不是「现在应该是什么样」。要修正历史记载，改 `docs/CHANGELOG.md`，不要改这里。

因此本目录**不参与节号校验**：它里面的 `§NN` 记的是 0.8.0 之前的编号，与当前站点的编号体系
没有对应关系，拿它去比对现行节号只会报出一堆假的失效。
